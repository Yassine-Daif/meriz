Where Merise comes from

Merise is a French method for analysing and designing information systems, developed in the late 1970s at the request of France’s Ministry of Industry. It is still taught in French technical and university courses because it addresses a lasting question: what data are we dealing with, and how should it be organised?

For data modelling, Merise progresses through levels. The conceptual model describes the domain. The logical model derives tables from it. The physical model adds types for a specific database system. Each level follows from the previous one through transformation rules, helping you spot design errors before writing SQL.

The data dictionary

Start by listing the information to manage in a data dictionary. Define each property once, with a name and type. A data item belongs in one place in the model; duplicating it creates the risk of conflicting values.

Consider a library. Useful data includes a member number, member name, book title, ISBN and borrowing date.

A common pitfall. Using name for both a member and an author hides two different properties. Give them distinct names, memberName and authorName, to make the rest of your model clearer.

Entities

An entity is an object in the domain whose information you want to store, such as a member, book or room. It has attributesfrom the dictionary, including an identifier that distinguishes each instance from all others.

Two entities are enough to start our library example.

An identifier can contain several attributes when one is not enough. For example, a cinema screening can be identified by its room and start time.

Relationships

A relationship connects entities. It is named with a verb describing what happens between them: a member borrows a book. Relationships can also have attributes when information belongs to neither connected entity on its own.

The borrowing date is a good example: it is not a property of the member or the book alone. It belongs to the event that connects them.

Cardinalities, at the heart of the model

Each connection between an entity and a relationship carries a pair of numbers: its cardinality. Read it from the entityto answer a precise question:

What is the minimum and maximum number of times one instance of this entity can participate in this relationship?

In our example, a member may never have borrowed a book, or may have borrowed many, giving 0,n. A book copy is borrowed by exactly one member at a time, giving 1,1.

The most common mistake. Reading the cardinality backwards, from the relationship. Always start at the entity and ask how many times one instance participates in the relationship. This determines the rest of the model, including where the foreign key goes.

From MCD to relational model

Transformation into the logical model follows defined rules. When the conceptual model is correct, these rules determine the tables.

Rule 1

Each entity becomes a table

Its attributes become columns, and its identifier becomes the primary key.

Rule 2

A relationship with a 1,1 or 0,1 side produces a foreign key

Place the foreign key on the side whose maximum is 1. In our example, a book participates once, so the Book table receives the member number. The relationship’s attributes follow it: the borrowing date is stored in Book.

Rule 3

A relationship with n on both sides becomes a table

When both connections have a maximum of n, neither entity table can hold all the relationship’s values. The relationship becomes a separate table with a primary key combining the connected entities’ identifiers. Its own attributes become columns.

From relational model to SQL

Now choose a database system. Concrete types appear at this stage: text becomes VARCHAR(255) or TEXT, an integer becomes INT, and a date becomes DATE. The conceptual model remains independent of these storage types.

Practise the method

You learn Merise by modelling. In Meriz, you draw the MCD, validate its rules and see the generated logical model, physical model and SQL. Changing a cardinality immediately shows its effect on the final database, helping you understand why it matters.
